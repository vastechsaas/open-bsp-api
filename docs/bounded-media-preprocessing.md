# Bounded media preprocessing

Scope: stop unnecessary media-preprocessing requests and accept the existing
internal scheduler credential. This does not change campaign retries, message
delivery, carousel media caching, or chatbot ownership.

## Behavior

- Disabled/archived organizations do not queue analysis requests.
- A private job row records at most three HTTP reservations per message.
- Queued HTTP work expires after two minutes; running analysis has a ten-minute
  lease. Duplicate or expired deliveries cannot start analysis.
- Recoverable processing failures wait one minute, then two minutes. The cron
  recovery scan is limited to 25 candidates per minute (hard cap 50).
- Expired final attempts are marked failed. The message is retained and marked
  preprocessing-complete so AI processing cannot wait forever.
- Completion appends artifacts through a lease-checked database operation; it
  does not replace customer content, receipt state, or assignment.
- Retry rows contain references, counters, and safe codes only. HTTP requests
  carry a message ID and lease token, not the full customer message.
- Both the configured EDGE_FUNCTIONS_TOKEN and the existing service-role
  credential are accepted. User JWTs and organization API keys are not.

## Delivery

1. Generate the additive migration from schema sources. Cron row data is not
   generated by schema diff: append the statement from
   supabase/schemas/07_cron/07-01_media_preprocessing.sql.
2. Apply and test locally; regenerate/synchronize types.
3. Back up the affected environment's cron definition and function sources.
4. Apply the migration, then deploy media-preprocessor immediately. It accepts
   both old webhook-shaped requests and new reference-only requests.
5. Before deploying campaign-worker's auth fix, confirm no unexpected legacy
   campaign sends are waiting. Do not change existing campaign transports.
6. Verify disabled organizations generate no preprocessing invocations, active
   fixture retries are bounded, and routine 401 traffic declines. Do not submit
   customer messages or call a campaign claimant as a health check.

## Rollback

Keep the bounded scheduler in place; never restore the old unbounded cron. Stop
new preprocessing scheduling before restoring an older processor, and retain the
additive job table and existing media. Never reset message delivery state or
replay completed campaign sends.

## Checks

- Deno tests cover internal auth, disabled/duplicate work, current-message
  loading, and retry recording without leaking provider payloads.
- SQL tests cover disabled insert/scheduler gates, exclusive reservations,
  backoff, three-attempt exhaustion including HTTP failure, stale workers,
  artifact preservation, and private worker grants.
